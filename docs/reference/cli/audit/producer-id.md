# `bifroest audit producer-id`

Prints the producer ID derived from a selected signing identity without reading the journal or creating a missing key.

```shell
bifroest audit producer-id default
```

## Syntax

<<cli_syntax("audit producer-id", "[flags] <auditlogName>")>>

<<cli_syntax("audit producer-id", "[flags] <auditlogName>", remote=True)>>

## Arguments

### `auditlogName` {: #argument-auditlogName }

`auditlogName` is the required configured name. Local use reads the signing private key; management reads the service's active identity.

## Flags {: #audit-producer-id-flags }

Includes [general executable flags](../index.md#general-flags).

<<flag("configuration", "File Path", "../../data-type.md#file-path", aliases=["c"], id_prefix="audit-producer-id-", heading=3)>>
Local configuration file; defaults to the [platform path](../usage.md#configuration). Unavailable with `@target` or direct SSH.

<<flag("format", "string", default="table", id_prefix="audit-producer-id-", heading=3)>>
Result format: `table`, `json`, `yaml` or `cbor`.

## Output

The default output is one lowercase 64-hex producer ID followed by a newline. Structured output contains the producer ID. A missing signing key produces an error and is never regenerated by this command.

The ID can be transferred; the private signing key stays on the server. To establish producer trust, obtain and retain the ID through an independently trusted channel. Merely querying it from the same untrusted source as the evidence does not create an independent trust anchor.

## Examples

### Retain producer trust after enabling audit or Recording

1. Configure and start [encrypted evidence capture](../../../guides/evidence.md#configure-the-recipient-and-server).
2. As the service user on the Bifröst host, obtain its producer ID:

    ```shell
    bifroest audit producer-id evidence
    ```

3. Retain the value separately and provision it on the workstation as described in [the verification guide](../../../guides/evidence.md#configure-the-verification-workstation).

## Availability

<<cli_availability(remote=True, direct_ssh=True)>>

The selected configuration entry must have audit logging or Recording enabled. Recording-only entries are supported. Artifact-transfer permission is not required.
